# 🤖 Розумник — Telegram-бот з ChatGPT

Телеграм-бот, який поєднує зручність Telegram і можливості моделей OpenAI:
розповідає випадкові факти, відповідає на питання, говорить від імені відомих
особистостей, проводить квіз із підрахунком балів, перекладає тексти
та радить фільми, книги й музику.

Фінальний проєкт **Модуля 1** курсу JavaRush.

---

## Можливості

| Команда | Кнопка меню | Що робить |
|---|---|---|
| `/start` | — | головне меню, скидає будь-який активний сценарій |
| `/help` | — | список команд |
| `/random` | 🧠 Цікавий факт | надсилає картинку і випадковий факт; кнопки «Ще факт» / «Закінчити» |
| `/gpt` | 🤖 Чат-бот | вільний діалог з моделлю: кожне питання обробляється окремо |
| `/talk` | 👤 Відома особистість | розмова з однією з 5 особистостей; бот **памʼятає** контекст розмови |
| `/quiz` | ❓ Квіз | питання з варіантами A-D за обраною темою, перевірка відповіді моделлю і рахунок |
| `/translate` | 🌐 Перекладач | переклад тексту на обрану мову, кнопка зміни мови |
| `/recommend` | 🍿 Що подивитись | добірка фільмів/книг/музики; кнопка «Не подобається» враховує все відкинуте |

## Стек

- **Python 3.12**
- **[aiogram 3](https://docs.aiogram.dev/)** — асинхронна робота з Telegram Bot API, FSM для станів діалогу
- **[openai](https://github.com/openai/openai-python)** — асинхронний клієнт `AsyncOpenAI`
- **python-dotenv** — змінні середовища

## Налаштування

Скопіюйте `.env.example` у `.env` і заповніть значення:

```bash
cp .env.example .env
```

| Змінна | Обовʼязкова | Що це |
|---|---|---|
| `BOT_API_KEY` | так | токен бота від [@BotFather](https://t.me/BotFather) |
| `OPENAI_API_KEY` | так | ключ OpenAI |
| `OPENAI_MODEL` | ні | модель, за замовчуванням `gpt-5.6-luna` |
| `OPENAI_REASONING` | ні | `reasoning_effort`: `none` для `gpt-5.6-luna`, `minimal` для `gpt-5-nano` |
| `OPENAI_MAX_TOKENS` | ні | максимум токенів у відповіді, за замовчуванням `600` |
| `OPENAI_TIMEOUT` | ні | таймаут запиту до OpenAI в секундах |
| `MAX_GPT_HISTORY` | ні | скільки останніх реплік памʼятає `/talk` |

> ⚠️ **`.env` не потрапляє в git** — він у `.gitignore`. Опублікований на GitHub
> ключ OpenAI автоматично відкликається за 10-20 хвилин.

Якщо обовʼязкові змінні не заповнені, бот не стартує і напише, чого саме бракує.

## Запуск

```bash
python main.py
```

У консолі зʼявиться `Запускаємо бота...` — можна писати боту `/start`.

### Як це влаштовано

**Шари.** Хендлер не знає, як влаштований OpenAI; `gpt.py` не знає, що існує Telegram.
Між ними — звичайні рядки. Якщо модель недоступна, `ask()` повертає `None`,
і хендлер сам вирішує, що показати користувачеві.

**Стани.** Кожен сценарій — це набір станів FSM і дані в них:
історія розмови для `/talk`, тема й рахунок для `/quiz`, мова для `/translate`,
список відкинутого для `/recommend`. Стан зберігається в `MemoryStorage`,
тому після перезапуску бота активні діалоги скидаються.

**Промпти — у файлах, а не в коді.** Щоб змінити характер бота, достатньо
відредагувати `resources/prompts/*.txt` і перезапустити бота.

**Додати нову особистість** у `/talk`:

1. промпт `resources/prompts/talk_<ключ>.txt`
2. картинка `resources/images/talk_<ключ>.jpg`
3. один рядок у `catalog.PERSONS`

Кнопка зʼявиться сама.

## Відмовостійкість

- усі помилки OpenAI (ліміт, таймаут, немає звʼязку, помилка API) перехоплюються —
  користувач отримує зрозуміле повідомлення, технічна причина йде в лог;
- порожня відповідь моделі обробляється окремо: у лог пишеться `finish_reason`;
- глобальний обробник `dp.error` ловить усе, що не спіймали хендлери, і відповідає
  користувачеві замість мовчазного падіння;
- текст поза будь-яким сценарієм не губиться — бот пропонує меню;
- кнопки зі старих повідомлень (після перезапуску бота чи `/start`) не ламають бот.

## Логування

Логи йдуть у `stdout` у форматі `час | рівень | модуль | повідомлення`.
Записуються вхід у сценарії, вибір особистості чи теми, помилки OpenAI
та необроблені винятки з повним трейсбеком.
